## 一、策略原理

### 1.1 资金费率是什么

永续合约(Perpetual Futures)是一种**没有到期日**的衍生品。问题是:既然没有到期日,价格怎么跟现货价挂钩?

答案是 **资金费率(Funding Rate)** 机制——一个 **多空之间的"交税"机制**:

- 当永续价格 > 现货价格(市场看多过热) → 资金费率为**正** → **多头每 8 小时给空头付钱**
- 当永续价格 < 现货价格(市场看空过头) → 资金费率为**负** → **空头每 8 小时给多头付钱**

这个机制的目的是把永续价格"拉回"现货价格附近。**钱不是交易所收的,是多空之间互转**——交易所只是扮演结算者角色。

> 不同交易所的结算频率不同:
> - Binance / OKX / Bitget / HTX:**每 8 小时**结算一次(00:00 / 08:00 / 16:00 UTC)
> - Bybit:**每 8 小时**(00:00 / 08:00 / 16:00 UTC)
> - Hyperliquid:**每 1 小时**结算(资金费小但频率高)
> - dYdX:**每 1 小时**

### 1.2 套利的核心思想

**关键观察**:在加密牛市或某些热门币种上,资金费率经常**长期为正**。这意味着多头持续给空头交钱。

**那如果我做空赚资金费,但又不想承担"币价下跌"以外的风险呢?**(注意——做空是赌跌,但我不想真的赌跌,我只想拿资金费)

**Delta 中性对冲**:
```
现货市场买入 1 BTC          (Delta = +1)
永续市场做空 1 BTC          (Delta = -1)
─────────────────────────
组合净 Delta = 0(价格涨跌都不影响我)
```

**结果**:
- BTC 涨 → 现货赚 + 永续亏 = 0
- BTC 跌 → 现货亏 + 永续赚 = 0
- **资金费率持续给我** → **稳定收入**

这就是**资金费率套利**的本质——**用 Delta 中性的姿势,白嫖多头给空头交的资金费**。

### 1.3 谁在亏钱给你?

很多人以为是"交易所亏钱",这是**错的**。让我们老实地理一下钱从哪里来:

```
牛市散户 / 杠杆多头(感觉要继续涨)
       │
       │ 每 8 小时付资金费
       ▼
做空一方(收到资金费)
       │
       │ 我们就站在这一侧
       ▼
我们(资金费率套利者)
```

**亏钱给你的,是那些不做对冲、纯做多赌涨的杠杆多头**。在牛市,这种人很多,资金费率经常涨到 0.05% 一次(年化 50%+)。但**这种钱不是免费的**——下面"风险"那节会展开讲。

## 二、数学模型

### 2.1 资金费率收益计算

**单次资金费率结算的收入**:
```
收入 = 仓位名义价值 × 资金费率
```

例如:
- 仓位:1 BTC 永续空单,BTC 价格 $60,000,名义价值 $60,000
- 当期资金费率:+0.01%
- 单次收入:$60,000 × 0.01% = **$6**

**年化收益率(Annualized Percentage Rate)**:
```
APR = 资金费率 × 每天结算次数 × 365
```

不同交易所:
- 8 小时结算:`APR = funding_rate × 3 × 365 = funding_rate × 1095`
- 1 小时结算:`APR = funding_rate × 24 × 365 = funding_rate × 8760`

例如 Binance 上 BTC 永续资金费率 0.01% / 8 小时:
```
APR = 0.0001 × 1095 = 10.95% 年化
```

例如 Hyperliquid 上 HYPE 资金费率 0.005% / 1 小时:
```
APR = 0.00005 × 8760 = 43.8% 年化
```

> **重要**:这个 APR 是**当期年化**,不是历史平均。资金费率每个结算周期都在变,有时为正有时为负,真实年化要用历史均值估算。

### 2.2 完整的净收益公式

刚才那个 APR 是**毛收益**。真实落到口袋里的钱要扣掉成本:

```
净 APR = 资金费 APR
       − 现货端手续费(年化)
       − 永续端手续费(年化)
       − 滑点(年化)
       − 资金机会成本(可选)
       + 借币利息(如果用借币 + 永续做空,有时能拿到补贴,稀有)
```

**手续费的年化估算**:

假设你 7 天进出一次仓位,即一年开关仓 52 次,**每次开关仓产生 4 笔交易**(开现货多 + 开永续空 + 平现货多 + 平永续空):

```
每笔交易费率(主流交易所 Maker):0.02% - 0.04%
单次开关仓总费率:4 × 0.03% = 0.12%
年化手续费成本:0.12% × 52 = 6.24%
```

⚠️ **这个数字告诉你一件事**:如果你看到的资金费率 APR 只有 5%,**扣掉手续费就是负的**——你越做越亏。资金费率套利的"最低进场门槛"通常是 **APR > 10%**,理想是 **APR > 15%**。

**滑点的年化估算**:
```
单边滑点:0.05% - 0.2%(取决于流动性)
单次开关仓滑点:4 × 0.1% = 0.4%
年化滑点成本:0.4% × 52 = 20.8%(频繁操作时巨大!)
```

⚠️ **这是为什么我们不做高频换仓**——每次开关仓都是钱。系统的设计是 **APR 跌破阈值才平仓,不是每天都换**。

### 2.3 净收益的三档区间

| 场景 | 资金费 APR | 手续费 | 滑点 | **净 APR** |
|---|---|---|---|---|
| 平淡市场 | 8% | -3% | -2% | **3%** ⚠️ 不值得做 |
| 一般机会 | 15% | -3% | -2% | **10%** ✅ 标准目标 |
| 牛市/热点 | 35% | -4% | -3% | **28%** 🔥 主力机会 |
| 极端热点 | 80% | -5% | -5% | **70%** ⚡ 注意流动性风险 |

### 2.4 为什么不能简单地"哪个 APR 高就做哪个"

看到这里你可能想:"那我就专挑 APR > 100% 的小币种做"。这是新手最常见的死法。原因:

**风险 1:资金费率会突然反转**
- 现在 +0.05%(APR 54%),下一期变成 +0.001%(APR 1%)甚至 -0.02%(负的)
- 你必须实时监控并平仓,否则赚的钱被亏回去

**风险 2:小币种现货价格剧烈波动 → 永续清算**
- 你的永续空单不是 1 倍杠杆,通常 3-5 倍(节省保证金)
- 如果币价突然涨 30%,永续空单可能直接被清算,但现货端的多头来不及覆盖损失
- **这是资金费率套利最大的爆仓原因**

**风险 3:小币种的"套利幻觉"**
- 看着 APR 80%,但流动性差,实际开仓滑点 1%+,扣完根本不赚
- 而且小币种容易**下架**,一旦交易所宣布下架,资金费率会归零或反转,你被迫平仓亏出场

**所以系统设计要做的是**:
- 综合评估 APR、流动性、波动率、市值,而不是只看 APR
- 实时监控资金费率变化,转负或低于阈值就退出
- 严格保证金率监控,接近清算线就主动减仓

## 三、执行流程(关键!)

这一节最重要——**如果执行错了,理论再美也是亏钱**。

### 3.1 开仓:4 条腿的原子化执行

资金费率套利的"一个仓位"实际上是**两条腿**(现货多 + 永续空),但**每条腿都涉及"挂单 → 成交"两个步骤**,所以总共有 **4 个动作**。任何一步失败,必须**全部回滚**,不能留单边敞口。

**正确的开仓顺序**:

```
Step 1:同时挂出两条腿的限价单(并行)
        ┌──────────────────────────────┐
        │ Binance 现货:买入 0.1 BTC   │
        │ 限价单 @ $60,005             │
        └──────────────────────────────┘
        ┌──────────────────────────────┐
        │ Binance 永续:做空 0.1 BTC   │
        │ 限价单 @ $60,000             │
        └──────────────────────────────┘

Step 2:等待两条腿都成交(timeout 5 秒)
        ✅ 都成交 → 进入 Step 4
        ❌ 只有一条腿成交 → 进入 Step 3
        ❌ 都没成交 → 取消订单,重试或放弃

Step 3:回滚处理(关键!)
        如果只有现货成交,永续没成交:
          → 立即取消永续未成交订单
          → 立即市价卖出已买的现货
          → 记录这次失败 + 损失,通知用户

        如果只有永续成交,现货没成交:
          → 立即取消现货未成交订单
          → 立即市价平仓永续
          → 记录失败 + 损失,通知用户

Step 4:确认仓位状态
        - Delta 是否真的接近 0(允许 ±1% 偏差)
        - 写入 Position Manager
        - 锁定资源
        - 推送通知"建仓成功"
```

### 3.2 为什么"原子化"这么重要

**举个真实场景**:

```
0.000s:你下了 ETH 现货买单($3,000)+ ETH 永续空单($3,000)
0.150s:现货成交了
0.151s:ETH 突然有大新闻,价格瞬间跳到 $3,030
0.500s:你的永续空单还没成交(因为限价 $3,000 没到这个价了)
        永续订单簿现在卖价是 $3,032
─────────────────────────────────────────
你现在的状态:
  - 持有 1 ETH 现货(成本 $3,000)
  - 没有永续对冲
  - 价格继续涨到 $3,100
  - 你以为对冲了,但其实是裸多
```

如果系统设计错了,**你以为自己 Delta 中性,实际上在赌涨赌跌**。当行情极端波动时,可能一夜亏掉 5%-10%。

**正确处理**:Step 3 的回滚机制——发现单边敞口立即用市价单关掉。市价单一定能成交,虽然滑点大,但**确定性 > 滑点**。

### 3.3 持仓监控(每秒级)

开仓后,系统持续监控这些指标:

```python
# 监控循环(每秒执行一次)
async def monitor_position(position):
    # 1. Delta 偏离检查
    delta = position.spot_size - position.perp_size
    if abs(delta / position.notional) > 0.01:  # 偏离超过 1%
        await rebalance_delta(position)

    # 2. 保证金率检查
    margin_ratio = await fetch_margin_ratio(position.exchange)
    if margin_ratio < 60:  # 安全阈值,不是清算线
        await reduce_position(position, ratio=0.5)
        await notify("WARN", f"{position.symbol} 保证金率 {margin_ratio}%,已减半仓")

    # 3. 资金费率方向检查
    current_funding = await fetch_funding_rate(position.exchange, position.symbol)
    if current_funding < 0:
        position.negative_funding_count += 1
        if position.negative_funding_count >= 2:
            # 连续两期负资金费 → 退出信号
            await close_position(position, reason="funding_negative")

    # 4. APR 阈值检查
    current_apr = current_funding * 1095  # 8 小时结算
    if current_apr < config.exit_when_apr_below:
        await close_position(position, reason="apr_too_low")

    # 5. 持仓时长检查
    if position.holding_hours > config.max_holding_hours:
        await close_position(position, reason="max_holding_time")
```

### 3.4 平仓:同样的原子化

平仓的逻辑跟开仓**镜像**——同样要并行、同样要 timeout、同样要回滚保护。

```
Step 1:同时挂出两条平仓单(限价)
        - Binance 现货:卖出 0.1 BTC
        - Binance 永续:平掉 0.1 BTC 空单

Step 2:等待成交(timeout 5 秒)

Step 3:如果一边成交一边没成 → 立即用市价单完成另一边

Step 4:计算最终 PnL,写入数据库,通知用户
```

### 3.5 资金费率结算时刻的特殊处理

每 8 小时结算资金费时,**永续合约会有短暂剧烈波动**——很多套利机器人会在结算前后的 1-2 分钟内调整仓位。

**系统设计**:
- **结算前 5 分钟**:不允许新开仓(除非是已存在持仓的对冲调整)
- **结算后 2 分钟**:不允许新开仓(等流动性恢复)
- **结算时刻**:监控你的持仓是否成功收到资金费,如果没有(可能是交易所故障),立即告警

## 四、出场策略

下面 5 个条件,**任何一个**满足就平仓:

| 条件 | 阈值(默认) | 理由 |
|---|---|---|
| **资金费 APR 跌破** | < 5% | 不值得继续承担风险 |
| **资金费连续转负** | 连续 2 期 | 趋势变了,反方向亏钱 |
| **保证金率低于** | < 50% | 接近清算线,安全第一 |
| **持仓时长超过** | > 168 小时(7 天) | 强制重新评估 |
| **单仓回撤超过** | > 5% | 异常情况,先平再说 |

**这 5 个条件是写死在代码里的逻辑,Tier 1 配置只能调阈值数字,不能取消条件本身**。

## 六、风险与亏损场景(最重要的一节)

我必须老实告诉你:**这个策略不是无风险的**。下面是实战中真实发生过的亏损场景,每一个我都讲清楚:**触发条件、亏损方式、系统怎么保护、你也防不住的部分**。

### 6.1 资金费率突然反转(最常见)

**场景**:你建仓时 APR 30%,持仓两天后市场情绪反转,资金费率从 +0.04% 变成 -0.02%。

**亏损方式**:
- 你持有空头 → 资金费率为负 → **你要付钱给多头**
- 持续 8 小时未平仓:亏 0.02% × 仓位
- 看着不多?**乘以你所有持仓 + 持续多期 = 真实亏损**

**系统保护**:
- 连续 2 期负资金费自动平仓(`exit_when_funding_negative_count: 2`)
- 但你已经亏了 2 期(约 0.04% × 仓位)

**你也防不住的部分**:从"刚建仓 APR 30%"到"开始转负"中间,你已经付出了开仓手续费和滑点。如果资金费率反转得快,你可能净亏。

**实战建议**:
- 进场前看历史资金费率(`funding_history_check`),过去 9 期至少 7 期是正的才进场
- 这能过滤掉"波动型"币种,只留下"稳定为正"的

---

### 6.2 永续清算(最致命)

**场景**:你在某小币种上建立资金费率套利,3 倍杠杆做空。币价突然 1 小时内涨 35%。

**亏损方式**:
- 永续空单保证金率被打到 0% → **强制清算**
- 现货多头还没来得及关掉,市场已经回落
- 最终结果:**永续亏 100%(被清算的部分)+ 现货也亏(回落了)**

**真实案例**:2024 年 5 月 PEPE 单日涨 60%,很多用 5 倍以上杠杆做资金费率套利的人爆仓——他们以为是 Delta 中性,但永续端杠杆太高,根本撑不到"对冲生效"。

**系统保护**:
- 强制最大杠杆 3 倍(`max_leverage: 3`)——这意味着币价要涨 33% 才会清算
- 保证金率低于 60% 时减半仓(`monitor_position` 中的逻辑)
- 保证金率低于 50% 时全平(Tier 3 红线)
- 持仓金额限制单币种 $500(`max_per_symbol: 500`)——单币种崩了最多亏 $500

**你也防不住的部分**:
- **极端跳空**:某些情况下币价会瞬间跳 50%+(币安服务器问题、深度突然消失),系统监控做不到毫秒级
- **交易所风控延迟**:你的减仓订单可能因为交易所拥堵而延迟成交

**实战建议**:
- **永远不要超过 3 倍杠杆**——哪怕看到 100% APR 也不要
- 单笔资金不超过 $500——这是 Phase 0 的硬上限
- 严格遵守 `min_listed_days: 30` 过滤,新币波动太剧烈

---

### 6.3 币种突然下架

**场景**:Binance 公告 PEPE 永续合约 7 天后下架。

**亏损方式**:
- 公告后 1 小时内,资金费率会被人为强制归零或反转
- 永续合约流动性骤降,你想平仓发现挂单根本没人接
- 被迫用市价单平仓 → 滑点可能 1%-3%
- 现货市场流动性也会受影响,跟着掉一波

**系统保护**:
- 通过监控交易所公告 API 提前发现下架信息(部分交易所支持)
- 资金费率连续转负 2 期触发出场

**你也防不住的部分**:
- 交易所突袭下架(罕见但发生过)——比如 FTX 倒闭前几小时,所有合约流动性瞬间消失
- 监管原因下架(没有提前公告期)

**实战建议**:
- 不做最近 30 天内才上线的新币(`min_listed_days: 30`)
- 不在小所做长期持仓(HTX、Bitget 上的小币种风险高)
- 每个币种持仓控制时长(`max_holding_hours: 168`)

---

### 6.4 交易所宕机或 API 异常

**场景**:Binance API 突然返回 502 错误持续 10 分钟。

**亏损方式**:
- 你无法平仓(API 不通)
- 你无法监控仓位(数据不更新)
- 在这 10 分钟内,如果币价剧烈波动,你完全无能为力
- 等 API 恢复时,可能已经亏了几个百分点

**系统保护**:
- API 错误计数超过 3 次/5 分钟 → 系统进入"暂停建仓"状态(Tier 3)
- WebSocket 断连超过 60 秒 → 触发熔断(Tier 3)
- 重要操作(平仓)有重试机制 + 备用 RPC

**你也防不住的部分**:
- **交易所完全跑路**:FTX、Mt.Gox 这种,你的资产可能直接归零
- **大规模 DDoS 攻击**:行情剧烈波动时常发生,API 集体瘫痪 30 分钟+

**实战建议**:
- 资金分散到 3-5 家交易所,不要把所有鸡蛋放一个篮子
- 每天至少检查一次系统日志,发现异常立刻处理
- 单交易所占比不超过总资金 50%(Tier 2 风控)

---

### 6.5 流动性枯竭(瞬时滑点暴增)

**场景**:你想平仓 10 ETH 永续空单,平时滑点 0.05%,但当下市场恐慌,订单簿深度只剩 2 ETH。

**亏损方式**:
- 你的市价单一吃就把订单簿吃穿
- 实际成交均价比中间价差 0.5%-2%
- 单次平仓多亏 $50-$200(按 $30,000 仓位算)

**系统保护**:
- 进场前流动性检查:订单簿前 5 档总深度 > $50,000(`min_spot_orderbook_depth_usd: 50_000`)
- 平仓时优先用限价单,timeout 后才转市价单
- 滑点超过 0.3% 取消订单(`max_slippage_pct: 0.3`)

**你也防不住的部分**:
- 极端行情下流动性会**瞬间消失**——你下完单的那 0.1 秒内,订单簿可能已经没人挂单
- 系统检查的是"过去某一刻"的流动性,不能保证下单时还存在

**实战建议**:
- 单笔仓位不要太大,$500 / $1000 这种规模一般不会触发流动性问题
- 不在恐慌行情下硬开新仓——等市场稳定再说
- 永远保留 20% 资金不动用,应对应急

---

### 6.6 跨所基差扩大

**场景**:你在 Binance 现货买 BTC,在 Bybit 做空 BTC 永续。两家价格平时差几美元,但某天突然 Binance 现货 $60,000 而 Bybit 永续 $61,500——基差扩大 2.5%。

**亏损方式**:
- 你看到的"组合 PnL"里,Binance 现货赚但 Bybit 永续亏更多
- 即使 Delta 中性,**基差扩大期间未实现亏损是真的**
- 你想平仓,但不平的话每天看着浮亏心慌
- 平掉就锁死了亏损

**系统保护**:
- 优先用同一交易所的现货 + 永续(基差最稳)
- 如果跨所,监控基差变化,扩大超过 1% 时通知(WARN 级别)

**你也防不住的部分**:
- 基差是市场决定的,你不能控制
- 某些极端行情下基差能维持几小时甚至几天

**实战建议**:
- **强烈优先选择同所建仓**(Binance 现货 + Binance 永续,而不是 Binance 现货 + Bybit 永续)
- 跨所做仅限"流动性极好的主流币"(BTC / ETH / SOL),不做小币种
- 跨所建仓时单笔金额减半

---

### 6.7 风险总结表

| 风险类型 | 发生概率 | 单次损失 | 系统能防住几成 |
|---|---|---|---|
| 资金费率反转 | 高(每周遇到) | 0.05%-0.5% | 80% |
| 永续清算 | 低(月度遇到) | 5%-30% | 90%(只要不超 3 倍杠杆) |
| 币种下架 | 低 | 1%-3% | 50%(部分能预警) |
| 交易所宕机 | 中(月度遇到) | 0%-2% | 60% |
| 流动性枯竭 | 中(行情极端时) | 0.2%-1% | 70% |
| 基差扩大 | 高(经常发生) | 0.5%-2% 浮亏 | 90%(同所建仓) |

## 七、回测要求

在写代码之前,这个策略**必须先用历史数据回测**,验证策略本身的逻辑是 work 的。

### 7.1 回测数据需求

**历史时间窗口**:**至少 12 个月**(包含一轮牛熊切换)

**数据频率**:
- 资金费率:每个结算周期(8 小时 / 1 小时)的历史值
- 现货价格:1 分钟 K 线
- 永续价格:1 分钟 K 线
- 订单簿深度:每小时一次快照(用于估算滑点)

**数据源**:
- **Binance / Bybit**:官方 API 都提供历史资金费率,免费,可下载
- **OKX / HTX / Bitget**:官方 API 也支持
- **Hyperliquid / dYdX**:官方 GraphQL API
- **第三方备用**:CoinGlass、Laevitas(付费,但更全)

**币种范围**:
- 必选:BTC、ETH、SOL、BNB(主流币,流动性极好)
- 推荐:DOGE、AVAX、ARB、OP、SUI(中等市值热门币)
- 可选:PEPE、SHIB、ENA、HYPE(波动性大,机会多但风险高)

### 7.2 回测要模拟的真实情况

回测最容易**美化结果**的就是没考虑真实成本。我们要把所有真实成本加进去:

**必须模拟的事**:

```python
# 真实回测引擎要做的几件事

1. 手续费:每笔进出按交易所真实费率扣
   - Binance Spot Maker:0.10%(VIP 0 级)/ 0.04%(BNB 抵扣后)
   - Binance Perp Maker:0.02%
   - 其他交易所类似

2. 滑点模拟:
   - 用历史订单簿深度估算
   - 大单按"吃多档订单簿"计算实际成交价
   - 默认假设 0.05% - 0.2% 滑点

3. 资金费结算时刻不能开仓
   - 模拟"前 5 分钟 + 后 2 分钟"禁止开仓窗口

4. 限价单不一定成交
   - 用 1 分钟 K 线的高低价估算限价单成交概率
   - 如果限价单 5 秒内没触达 → 转市价单 → 滑点更大

5. 资金费率会变
   - 不能假设"建仓时的 APR 一直持续到平仓"
   - 用历史每期实际资金费率累加

6. 仓位上限的实施
   - 单币种不超过 $500
   - 总仓位不超过 50%
   - 同时仓位不超过 5 个

7. 交易所 API 异常
   - 模拟 1% 概率的"下单失败 → 重试 → 滑点 0.3%"
```

### 7.3 关键指标(回测出来后看这些)

回测跑完后,看这些数字判断策略是否 OK:

| 指标 | 含义 | 通过标准 |
|---|---|---|
| **Total Return** | 总收益率 | > 12%(年化) |
| **Sharpe Ratio** | 夏普比率(收益/波动) | **> 1.5(关键!)** |
| **Sortino Ratio** | 索提诺比率(只看下行波动) | > 2.0 |
| **Max Drawdown** | 最大回撤 | < 8%(单月内不超 3%) |
| **Win Rate** | 胜率(每个仓位盈利占比) | > 70% |
| **Avg Holding Hours** | 平均持仓时间 | 24-72 小时 |
| **Total Trades** | 总交易次数 | > 200(样本量充足) |
| **Profit Factor** | 盈亏比(总盈利/总亏损) | > 2.0 |
| **Calmar Ratio** | 年化收益 / 最大回撤 | > 2.0 |

**最重要的两个**:

1. **Sharpe Ratio > 1.5**——低于这个就说明波动性吃掉了大部分收益,不值得做
2. **Max Drawdown < 8%**——这是 12 个月的最大回撤,超过 8% 说明风控不够紧

### 7.4 回测通过标准

**全部满足才算通过**:

- ✅ Sharpe > 1.5
- ✅ Max DD < 8%
- ✅ Win Rate > 70%
- ✅ 在 12 个月里**至少 8 个月是盈利的**(避免"全靠某一波牛市赚的钱")
- ✅ 在熊市月份(2022 年 5 月、2024 年 8 月这种)**最大单月亏损不超 3%**
- ✅ 单次最大亏损 < 5% 仓位

**任何一项不达标 → 回到设计阶段调参数,不能进 paper trading**。

## 八、Paper Trading 阶段

回测过了不代表实盘也行。Paper Trading 是"用真实行情、模拟订单"验证 2 周。

### 8.1 检查清单

```
☐ 系统连续运行 14 天无重大故障
☐ 模拟订单的成交率 > 90%
☐ 模拟实际收益与回测预测的差距 < 30%
   (例如回测预测月化 1.5%,实际跑出来在 1.0% - 2.0% 区间内)
☐ 触发熔断时系统正确停机
☐ Telegram / Discord 通知都正常发出
☐ Delta 偏离监控正常工作
☐ 资金费率结算时刻系统正确处理
☐ 至少经历过一次"资金费率反转"场景,系统正确平仓
☐ 至少经历过一次"模拟 API 错误",系统正确暂停
☐ PnL 归因报表正确(收益来源、手续费、滑点都能拆分)
```

### 8.2 与回测结果对比

如果 Paper Trading 跑出来的结果**远差于回测**(比如回测说月化 2%,实际只跑出 0.3%),原因通常是:

1. **滑点估算偏低**——真实订单簿比你估算的浅
2. **限价单成交率偏低**——市场变动比你想的快
3. **API 延迟更高**——监控反应慢,错过了好的进场点
4. **交易所手续费没算对**——用的是 VIP 等级费率而不是你的实际等级

**遇到这种情况**:回到代码调参数,不要硬上实盘。

### 8.3 Paper Trading 不通过怎么办

如果跑了 2 周还是不达标:

- **延长 Paper Trading 1 个月**,看是不是市场情绪问题
- 检查代码是否有 bug,特别是订单逻辑
- 重新跑回测,看回测假设是否过于乐观
- **可能需要回到设计阶段**——这是 OK 的,这就是 Paper Trading 的目的

## 十、与其他策略的协同

资金费率套利不是孤立的,系统里还有 4 个策略。**它们之间会抢资源**,必须设计协同机制。

### 10.1 资源冲突的几个场景

**场景 A:与"期现套利"完全重叠**

期现套利的机制是:**现货多头 + 永续空头**——这跟资金费率套利**一模一样**。

那为什么是两个策略不是一个?

**区别**:
- 资金费率套利的**入场信号**是:资金费 APR > 阈值
- 期现套利的**入场信号**是:永续价格 - 现货价格 > 阈值(基差)

通常这两个信号同时出现(资金费高 → 永续比现货贵 → 基差大),但偶尔会分离。

**协同方案**:
- Position Manager 资源锁 `{exchange}:{symbol}:{side}` 保证同一个币只能被一个策略占用
- 谁先扫到机会,谁先建仓
- 另一个策略发现资源被占用,自动跳过

**场景 B:与"跨所基差套利"部分重叠**

跨所基差套利:在 A 所做永续多头,在 B 所做永续空头(吃两个交易所之间的资金费率差)。

如果资金费率套利已经在 Binance 做了"现货多 + 永续空",而跨所基差套利想在 Bybit 做永续空——**理论上 OK**(两个不同交易所),但要注意总仓位不要超标。

**协同方案**:
- 账户级风控:单币种总仓位不超过 20%(包括所有策略加起来)
- 单交易所占比不超过 50%

**场景 C:与"期权波动率"无冲突**

期权策略主要在 Deribit 上跑,跟现货 / 永续不在同一个交易所——天然隔离。

### 10.2 资金分配建议

Phase 0 的 $5,000 总资金,推荐分配:

```
资金费率套利       $2,000    (40%)
期现套利           $1,000    (20%)  ← 暂时不做,留资金
跨所基差套利       $1,000    (20%)  ← 暂时不做
CEX-DEX 监控       $0       (0%)   仅监控,不交易
期权波动率         $500     (10%)  ← 暂时不做
预留保证金         $500     (10%)  应急
```

**Phase 0 实际只跑资金费率套利一个策略**,其他策略的资金留着,等第二个策略上线时再激活。

### 10.3 启用顺序建议

```
第 1 个上线:资金费率套利(主力)
第 2 个上线:期现套利(几乎是同一个策略,验证简单)
第 3 个上线:跨所基差套利(需要跨所资金调度)
第 4 个上线:CEX-DEX 监控(只监控,无下单)
第 5 个上线:期权波动率(资金达到 $30k+ 再考虑)
```

每个策略上线之前,前一个策略**必须已经在实盘稳定运行 2 周以上**。
