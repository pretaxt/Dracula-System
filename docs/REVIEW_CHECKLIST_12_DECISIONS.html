DECISION 1.1

月化收益预期 1%-3%

普通
是什么
整套系统 Phase 0 阶段(资金 $5k-$30k)的合理月化收益预期,作为"系统是否正常工作"的基准线。
关键数字
差
1% / 月
中
2% / 月
好
3% / 月
$35k 月化 2%
$700
不同意的后果
如果你期待 10%+/月,你会感觉"系统不行" → 加大杠杆 / 缩短测试 / 跳过风控 → 这是该行业 80% 散户失败的原因。真实结果:2-3 个月内大概率爆仓。
给"全职 + $35k"的具体建议
$700/月不够全职生活费 — 这是为什么 runway 重要。心理上准备好:前 3-6 个月这个项目几乎没收入。

DECISION 1.2

8-12 周开发周期

普通
是什么
从今天到第一个策略实盘上线的预期时间。8 周乐观 / 10 周合理 / 12 周保守。不要少于 6 周(必然跳过 paper trading)。
关键数字 · 8-12 周分配
Week 1-2: 项目骨架 + 数据库 + 配置系统
Week 3-4: Binance 适配器 + 资金费率扫描
Week 5-6: 风控引擎 + Position Manager
Week 7-8: 回测框架 + 第一个策略验证
Week 9-10: Paper Trading 14+ 天
Week 11-12: 实盘 $500 stage 1 + 调优
不同意的后果
想 4-6 周上线 = 必然跳过 paper trading,实盘第一周 80% 概率出大问题(订单失败处理不完善 / WS 断连 / 资金费率结算时机错)。修 bug 时是真金白银亏损。

DECISION 1.3

资金阶梯放大($500 → $1k → $2k → $5k)

高
是什么
实盘阶段资金不能一次到位,必须每个阶段验证后再加。每个阶段至少 14 天,通过后才进下一阶段。
关键数字
Stage 1
$500 / 14d
Stage 2
$1,000 / 14d
Stage 3
$2,000 / 14d
Stage 4
$5,000 / 30d
为什么这样设计
系统的 bug 通常在前 2 周暴露。资金 10 倍小时,bug 暴露成本也 10 倍小。$500 阶段如果有 bug,最多损失 $500。直接 $5k 上线如果有同样 bug,可能损失 $5k。
不同意的后果
$5k 一次到位:第一次 bug 损失放大 10 倍 → 心理上无法承受 → 紧急关停系统 → 系统未充分测试 → 失去修复动力。

DECISION 2.3

Tier 3 风控锁定(改 yaml + 重启才能修改)

极高
是什么
最严的风控参数(单日回撤红线、保证金率、API 错误熔断)不能在 UI 上修改,必须停机 → SSH → 改 risk.yaml → 重启。整个过程 5-10 分钟,有意制造摩擦。
为什么这样设计
这是为了对抗"未来你"。某天系统连续 3 天亏损,情绪化的你会想"今天行情特殊,临时关掉吧"。关掉之后:亏损扩大到 -10% / -20%。有意制造摩擦,让你"想改"和"真的改"之间隔 10 分钟冷静期。
不同意的后果
Tier 3 可在 UI 改:你某天情绪化决策时能立刻改。复盘时你会发现:"我那天不该改的"。LUNA 散户、FTT 散户、312 散户的剧本。

三、策略组合
DECISION 3.1

Phase 0 只跑 3 个策略,不跑 17 个

普通
是什么
Phase 0 阶段(0-12 周,$5k 实盘)实际上线的策略只有 3 个:#1 资金费率套利($2k)+ #4 期现套利($1k)+ #13 三角套利($500)。
为什么这样设计
如果 17 个一起跑,$5k 摊到每个不到 $300。每个策略持仓 < $100。手续费占比太高,几乎赚不到钱。"全做" = "全做不好"。
不同意的后果
坚持上更多:8 周不够 → 时间被压缩 → 每个都不达标 → 资金分散 → 每个都赚不到钱 → 注意力分散 → 不知道哪个赚钱哪个亏钱。

DECISION 4.1

回测必须 Sharpe>1.5 / Max DD<8% / Win Rate>70%

普通
是什么
每个策略必须先在 12-24 个月历史数据上回测,达到 3 个标准才能进入 Paper Trading 阶段。
关键数字
Sharpe
> 1.5
Max DD
< 8%
Win Rate
> 70%
年化
> 15%
为什么 Sharpe > 1.5(不是 1.0)
顶级 quant 基金长期 Sharpe 0.8-1.2。我们要 1.5 是因为回测高估实盘 0.5。回测 1.5 → 实盘大概率 1.0。回测 1.0 → 实盘大概率 0.5(不值得做)。
不同意的后果
完全跳过回测:实盘第一周必出大问题,这是 95% 失败者的共同特征。
提高到 Sharpe > 2.0:几乎没有策略能达到。你会"过度优化"参数 → 严重过拟合 → 实盘归零。
你的态度
DECISION 4.2

Paper Trading 至少 14 天才能进实盘

普通
是什么
回测过了之后不能直接实盘。必须用实时行情 + 模拟订单跑 14 天,验证执行链路。
为什么这样设计
回测验证"理论" → 历史数据 + 模拟执行,发现不了延迟、滑点、API 限流等"现实问题"。
Paper Trading 验证"工程" → 真实环境 + 模拟订单,暴露所有现实世界的边界情况。例如 Binance 凌晨 4 点的资金费结算时间窗口、WS 断连后 30 秒内没收到推送、某币种突然暴涨订单簿深度不够。
不同意的后果
跳过 Paper Trading:实盘第一周必出问题(80% 概率)。真金白银亏损 → 心态崩 → 早期放弃。

DECISION 5.2

多用户授权层是 Phase 2(核心系统稳定 3 个月后才做)

普通
是什么
第 12 章不在开发计划的前 12 周里。先做单租户(只有你)稳定 3 个月,再做多用户。最早第 9 个月朋友才能用上。
为什么这样设计
多用户层会让你工作量翻倍(用户认证 + 三层加密 + 数据隔离 + UI 共 1.5-2 个月)。如果同时做多用户 + 自己策略:你前 6 个月几乎全在救火。多用户 bug → 朋友资金风险。
不同意的后果
前 12 周就做多用户:你两件事都做不好。多用户系统有 bug → 朋友资金安全风险。自己策略受影响 → 自己也亏 → 关系破裂。
