# 05 · CEX-DEX 套利策略 · 完整设计

> **策略类型**:`cross_exchange_arb`
> **优先级**:🟠 P2(只监控,不自动执行)
> **预期月化收益**:**仅监控提示,需用户手动操作**
> **资金需求**:不直接占用,但建议预留 $500-$1000 操作资金
> **策略复杂度**:⭐⭐⭐⭐(高,即使只是监控)

---

## 序言:为什么这个策略只监控不自动执行?

我必须在最开头**老实告诉你一件事**:CEX-DEX 套利**自动执行的难度是 CEX 内部套利的 5-10 倍**,而且容易亏钱。我不会让系统自动做这件事。

**核心问题**:
1. **MEV 攻击**:你的 DEX 交易在区块打包前是公开的,机器人会"三明治攻击"你
2. **Gas 成本不可预测**:同一笔交易,Gas 可能 $5 也可能 $50
3. **跨链桥接慢**:CEX 提币到链上、链上转回 CEX,几分钟到几小时
4. **滑点深不见底**:DEX 池子深度有限,大单滑点超出预期
5. **价差转瞬即逝**:套利窗口经常只有几秒,人工操作根本来不及

**专业的 MEV 团队**(searcher)有 co-located 服务器、私有 mempool 通道、Flashbots bundle、自研合约——他们早就把所有 0.5% 以上的价差吃掉了。剩下给我们的是**残羹剩饭**。

**所以这个策略的设计是**:
- ✅ **实时监控**所有 CEX 和 DEX 的价差
- ✅ **过滤掉**扣完成本后无利可图的机会
- ✅ **推送通知**真正有利润的机会(扣 Gas、滑点、桥接费后净 > 0.5%)
- ❌ **不自动下单**

如果你看到通知后想手动操作,系统会给你一个**详细的执行建议**(去哪个 CEX 买、多少量、用什么 RPC、Gas 估值多少),你自己决定要不要做。

## 一、策略原理

### 1.1 CEX 和 DEX 的价格为什么会有差异?

理论上同一币种在不同市场应该同价,但实际:

**信息传递的速度差异**:
- CEX 内部信息传递快(订单簿匹配引擎几毫秒响应)
- DEX 是链上 swap,出块时间(以太坊 12 秒,BSC 3 秒,Solana 0.4 秒)
- 信息从 CEX 传到 DEX 需要"套利者搬运"
- 在套利者搬运过程中,**价差短暂存在**

**资本流动的限制**:
- CEX 充值 / 提币需要时间(几分钟到几小时)
- 跨链桥需要时间和费用
- 这种"摩擦"让套利不能瞬间完成,**价差能维持几秒到几分钟**

**长尾币种**(meme 币、新币):
- CEX 还没上线,只能在 DEX 交易
- 一旦 CEX 上线,DEX 流动性会被吸走,价差短暂巨大
- 这是 CEX-DEX 套利**最大的机会窗口**

### 1.2 套利的两种方向

**方向 A:CEX 便宜,DEX 贵**
```
1. CEX 买入 ETH(便宜)
2. CEX → 自己钱包(链上提币,5-30 分钟)
3. DEX 卖出 ETH(贵的)
4. DEX → CEX(再充值回去,如需)
```

**方向 B:DEX 便宜,CEX 贵**
```
1. DEX 买入 ETH(便宜)
2. 钱包 → CEX(充值,5-30 分钟)
3. CEX 卖出 ETH(贵的)
```

**关键**:中间的"搬运"步骤需要时间,在此期间价格会变化。所以**真正聪明的做法是**:**不搬运,在两边各持有一些资金,看到价差直接两边同时操作**。

### 1.3 我们系统的"准实时"模式

**我们不做"搬运型"套利**,因为成本太高。我们做"两边都有资金"的套利:

**前提**:
- CEX 上常驻 $1000 USDT
- DEX 钱包(MetaMask)常驻 $500 USDT + $500 等值的某币

**操作**:
- 当 DEX 上某币便宜时:在 DEX 用 USDT 买入该币 + 在 CEX 卖出同等数量该币
- 当 DEX 上某币贵时:反之

**结果**:
- 钱包里币的总量不变(一边减一边加)
- 钱包里 USDT 总量增加(净赚价差)
- 资金不需要搬运,只是"再平衡"

**但**:这种操作仍然需要手动,因为 DEX 端的执行速度、Gas 控制、MEV 防护**都需要人工判断**。

## 三、价差识别

### 3.1 计算公式

```
原始价差 = (DEX 价格 - CEX 价格) / CEX 价格 × 100%
```

### 3.2 真实可执行价差(扣除所有成本)

```
净价差 = 原始价差
       - CEX 手续费(双向 0.1% - 0.2%)
       - DEX swap 手续费(0.05% - 1%,看池子)
       - DEX 滑点(取决于流动性)
       - Gas 费(占订单金额的百分比)
       - 桥接费(如果跨链)
```

**示例:PEPE/USDT 价差监控**:

```
CEX(Binance):$0.00001234
DEX(Uniswap V3):$0.00001281
原始价差:+3.81%

成本估算(交易 $1000):
  Binance taker fee:0.1%
  Uniswap swap fee:0.3%(0.3% pool)
  Uniswap 滑点(估):0.5%
  Gas(以太坊主网):$15(占订单 1.5%)
  ─────────────────────
  总成本:2.4%

净价差:3.81% - 2.4% = 1.41%
按 $1000 算:净利润 $14.1
```

⚠️ **关键洞察**:同样的 3.81% 原始价差,在不同链上的可执行性差异巨大:

| 链 | Gas 成本($1k 交易) | 净利润 |
|---|---|---|
| 以太坊主网 | ~$15 | $14 |
| Arbitrum | ~$0.30 | $28.5 |
| Base | ~$0.20 | $28.6 |
| BSC | ~$0.40 | $28.4 |

**所以系统优先推送 L2 / BSC 上的机会**。

```

  CEX taker:$1.00
  DEX swap:$3.00
  滑点(估):$5.00
  Gas:$15.00
  ─────────────
  总成本:$24.00

净利润:$14.10(1.41%)

⚠️ 注意:
  - 当前 ETH Gas 42 gwei,正常水平
  - Uniswap 池子深度 $850k,$1k 交易滑点 ~0.5%
  - 此机会预计窗口 30 秒

执行步骤建议:
  1. Binance 现货买入 81m PEPE($1000)
  2. 钱包提到 ETH 主网(已有的钱包)
```

### 5.2 不推送的情况

- 净利润 < $5(不值得操作)

- DEX 池子深度 < $100k(滑点不可控)

### 5.3 推送渠道

只发到 **Telegram / Discord**(需要用户主动看,不打扰其他事)。**不进 toast**(避免在仪表盘上太多干扰)。

## 六、风险与亏损场景

虽然系统不自动执行,但用户手动操作时可能踩这些坑:

### 6.1 MEV 三明治攻击(最大风险)

**场景**:你在 Uniswap V3 准备卖出 $5000 PEPE。

**MEV 机器人的操作**:
1. 监控 mempool,发现你的交易
2. **抢先在你前面卖出 PEPE**(让池子价格降低)
3. 等你的交易执行(成交价更差)
4. **在你后面买回来**(吃掉差价)

**结果**:你以为能拿 1.5% 利润,实际只拿到 0.3%-0.8%,差价被 MEV 机器人吃了。

**防御方法**:
- 用 **Flashbots Protect RPC**(免费):https://rpc.flashbots.net
- 用 **MEV Blocker**(免费):https://mevblocker.io
- 这两个 RPC 会把你的交易直接发给区块构建者,不进入公开 mempool
- **大额交易必须用**

### 6.2 Gas 突然飙升

**场景**:你在 Arbitrum 操作,Gas 平时 0.05 gwei。某 NFT mint 活动 + 某主流币暴涨,Gas 涨到 5 gwei。

**亏损**:Gas 成本可能从 $0.30 涨到 $30,直接吃掉所有利润。

**防御**:执行前**实时检查 Gas**,超过 1 gwei 不操作。

### 6.3 价差消失(最常发生)

**场景**:系统推送了机会,你点开 Telegram、复制信息、登录 Binance、登录 MetaMask、批准交易……一共花了 2 分钟。

**结果**:价差早已消失,可能反而变成负的(Binance 价格涨了 1%)。

**防御**:
- **手快**——5 秒内决定要不要做
- **预留 USDT** 在两边,跳过"提币"步骤
- 不可执行就放弃,不要硬上

### 6.4 链上交易失败

**场景**:你提交了 Uniswap swap,但因为滑点保护,交易失败但 Gas 没退。

**亏损**:$5-$30(取决于链)

**防御**:
- 设置滑点保护时合理(0.5% - 1%)
- 用 1inch Fusion 等带保护的聚合器
- 准备好"失败重试"的心理预期

### 6.5 钱包私钥被盗

**场景**:你为了方便,把钱包私钥放到笔记本里。某天电脑被入侵,钱包资金被瞬间转走。

**亏损**:钱包内全部资金

**防御**:
- 私钥绝对不能进 git、不能截图、不能存云盘
- 用专门的"交易钱包",只放小额($500-$1000)
- 大额资产存硬件钱包(Ledger / Trezor)

## 七、为什么这个策略对你的价值依然很大

读到这里你可能想:"既然不自动执行,那这策略意义在哪?"

**意义**:

1. **市场情绪的早期信号**:CEX-DEX 价差扩大,通常**先于价格大波动**。看到 PEPE DEX 价格突然比 CEX 贵 3%,可能是某个事件即将发生
2. **学习市场结构**:观察价差什么时候出现、持续多久,你会理解市场微观结构
3. **手动执行的小额机会**:每月可能有 5-10 次净利润 > $50 的机会,熟练后 10 分钟一次操作可以多 $500/月
4. **未来扩展**:等 Phase 1 之后,可以考虑接入专业 MEV 服务(比如 Flashbots Builder API),实现自动化

## 十、与其他策略的协同

CEX-DEX 套利**不占用其他策略的资源**:

- 不抢 CEX 永续仓位
- 不抢 CEX 现货仓位(只是"参考价格",不主动买)
- 唯一冲突:同一币种的 DEX 钱包余额

**资金分配**:
- DEX 钱包独立,不在策略资金分配里
- 总资金的 10%-20% 放 DEX 钱包

## 十一、总结

5 句话:

1. **本质**:监控 CEX 和 DEX 之间的价差,推送有利润的机会给用户
2. **不自动执行**:因为 MEV 攻击、Gas 不可控、操作复杂,自动化容易亏钱
3. **优先级**:L2 / BSC 上的机会(Gas 低)优先推送
4. **真正的价值**:不是直接赚钱,是给用户提供市场信号 + 手动套利机会
5. **未来扩展**:Phase 1+ 可以接入 MEV 服务,实现自动化
